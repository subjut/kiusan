# Prompt log

Verbatim log of the prompts given to the agent in this repository, grouped
per session day. The prompts are the project's steering history: they
survive agent-session compaction and can be handed to a fresh agent
verbatim.

Conventions:

- Prompts are quoted exactly as given, typos and all.
- A short note follows each prompt: what it produced or decided.
- Entries marked *(wording lost)* belonged to a compacted conversation
  whose summary preserved only the substance.
- Transcript markers like "function call failed" in Zed's thread history
  are failed agent tool calls (e.g. truncated write batches), not user
  prompts, and are not logged here.
- Entries are appended automatically with every prompt — verbatim plus
  a one-line outcome note, written before the session summary (rule in
  `AGENTS.md` → Conventions).

## 2026-10-25 — timezone select fix, curated zone list

1. "Condense the `timezones.txt` list to the most important ones, with maximun 2 locations per timezone. Also the timezone field on the form only shows the prefilled timezone. I can't actuall select a different timezone. Is the dropdown implemented correctly?"
   → Explained + fixed: `<datalist>` only suggests, and the suggestions
     are filtered by the text already in the field — with the prefilled
     zone in a text input, Chrome shows just that entry and Firefox offers
     no dropdown at all, hence "unselectable". The field is now a real
     `<select>` (server-rendered options; `dater.js` adds the browser's
     zone client-side when missing, prefill unchanged), and
     `data/timezones.txt` was condensed to 13 curated zones (max 2 per
     region + UTC); smoke test and AGENTS.md updated.
2. "Your form fix for the timezone is broken. It's now a dropdown, but still only shows my own timezone. Additionally, there is now the reduced list below the dropdown in form of non selectable text. Fix it, so there is only the dropdown. The reduced list was reduced too much. There should be about 2 selectable locations per timezone and region (so for example, for the UTC zone, choose one or two in Europe/ region and one or two in Africa/ region)."
   → Fixed: a fuzzy edit had left the options outside an immediately
     closed `<select>` (empty dropdown + the zone list rendered as loose,
     non-selectable text; the JS-added browser zone then was the select's
     only option). Template corrected; smoke test now asserts the options
     are *inside* the `<select>` (structure check). List rebuilt to spec:
     1-2 most important zones per UTC offset per region (86 zones + UTC,
     grouped by offset with `#` comments, which the loader now skips);
     two unloadable names replaced (`Pacific/Tonga` → `Tongatapu`,
     `Pacific/Port_Vila` → `Pacific/Efate` — absent from this host's
     tzdata).
3. "Order the dropdown alphabetically."
   → `timezoneList` is now sorted alphabetically at process start (the
     data file keeps its offset grouping for maintainers), `dater.js`
     inserts a client-appended browser zone at its alphabetical position,
     and the smoke test pins alphabetical rendering.
