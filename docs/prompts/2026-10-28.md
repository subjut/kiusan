# Prompt log

Verbatim log of the prompts given to the agent in this repository, grouped
per session day. The prompts are the project's steering history: they
survive agent-session compaction and can be handed to a fresh agent
verbatim.

Conventions:

- Prompts are quoted exactly as given, typos and all.
- A short note follows each prompt: what it produced or decided.
- Entries marked *(wording lost)* belonged to a compacted conversation
  whose summary preserved only the substance.
- Transcript markers like "function call failed" in Zed's thread history
  are failed agent tool calls (e.g. truncated write batches), not user
  prompts, and are not logged here.
- Entries are appended automatically with every prompt — verbatim plus
  a one-line outcome note, written before the session summary (rule in
  `AGENTS.md` → Conventions).

## 2026-10-28 — unified answer table (proposal)

1. "I commited all the changes.
   Now, The voting page is too cluttered. Move the voting down into the answer able itself. So, the table should display all votes already given, and as the last row an empty row with the name field on the left and for each date/time slot the applicable options. Below the table should be the submit button.
   Additionally, the edit and delete functionality should also be integrated into the table. So a returning user should see an edit button and a delete button, for example a pencil symbol and a trash bin symbol, preferably in front of his name.
   Do you have any other suggestions? Ask if anything is unclear.
   Give me a proposal for an implementation, don't implement yet."
   → Proposal only, no code changed: one unified answers table (respondent
     rows + a form row), pencil/trash icons in front of the name, in-place
     row editing via a `?edit=<id>` GET param (recommended), a single submit
     bar below the table, the separate answer form and the admin
     per-respondent cards both removed; POST handlers, store, cookie/CSRF
     and expiry semantics all unchanged. Awaiting the user's call on the
     open questions (edit in place vs. bottom row; explicit red X button).

2. "In place — that row becomes the editable row at its position in the table (my preference: the pencil stays with the name being edited)"
   → Confirmed in-place editing (red X button kept as decided). Implemented:
     one unified answers table — a static row per respondent plus exactly
     one form row (empty last row when the viewer has no answer, or the
     opened row in place via `?edit=<id>`, validated per view: a user link
     may only open its own row, an admin link any row, someone else's row
     posting through the capability `/answer/edit` endpoint with a hidden
     `respondentid`); pencil/trash inline-SVG icons in front of the name
     (own row in the user view, every row in the admin view), a hidden
     per-page delete form filled by the trash icons with a named
     confirm dialog, one submit/cancel bar below the table, per-cell mark
     toggles (green / yellow / red ✗, single-slot grey-out per cell),
     own-row and form-row highlighting in the name column. POST handlers,
     store, cookie/CSRF and expiry all unchanged; poll suite pins the new
     render states (icons, in-place edit row, user-link `?edit` rejection,
     unknown target). go build/vet and the full `-race` suite green on
     both backends.

3. "Fix both oddities. Additionally, there is a bug: The names (and also edit and delete buttons) of the respondents appear above the table, not in the first column. Fix it."
   → Root cause was in the template source, not the engine: the
     unified-table rewrite left the header row and every name cell as a
     `<tr></tr>`/`<td></td>` tag immediately closed, with the row/cell
     content hoisted outside the tag — HTML5 drops the stray closers and
     the hoisted content renders as a row above the table (the string
     pins in poll_test.go couldn't see the structural break). Re-merged
     each into proper `<tr>`…`</tr>`/`<td>`…`</td>` pairs, removed the two
     stray `</label>` closers in the admin link box (oddity 2), and ran
     `gofmt -w database/database.go` (oddity 1). Verified via a rendered
     byte dump plus the full `-race` suite green on both backends.

4. "I commited everything.
   Pudge hasn't receive any updates for a long time. It might be abandoned. Remove the Pugde database option and make sqlite the default."
   → Removed the Pudge backend entirely (`store/pudge.go`, the
     `BackendPuge` constant, `TestPollPuge`/`TestSmokePuge`/
     `TestFormPostPuge`, the `recoilme/pudge` go.mod dependency — it has
     no transitive deps of its own) and made sqlite the default: an empty
     `KIUSAN_STORE` now opens sqlite with the default `./meetings.db`.
     Comments in `store.go`/`database.go` updated, `AGENTS.md` rewritten
     to match, `meetings.db` added to `.gitignore`; the orphaned dev data
     files `meetings`/`meetings.idx` deleted at the user's choice. `go
     build`, `go vet` and the full `-race` suite (now sqlite-only) green.

5. "Comitted.
   Since there have been no releases, there does not need to be any backward compatibility. Is there any such compatibility code?"
   → Inventory found three shims for data shapes the current UI can no
     longer create: empty `AdminKey` (nullable unique column + the test
     that simulated legacy polls; no handler code branched on it), nil
     `Expires` (the 90-day `legacyCookieAge` cookie, nil branches in
     `poll.go`/`main.go`, `{{if .ends}}` in the template), and empty
     `TimeZone` → UTC. Per the user's decision, (1) and (2) were removed
     — `AdminKey` is now `not null;uniqueIndex`, `Expires` a required
     `time.Time` — while (3) was kept as a *documented fallback* (same
     behavior, "legacy" wording dropped). Also fixed the pudge-era
     "admin key index entry" wording in the store's `Delete` doc. Note:
     auto-migrate is additive-only, so any pre-existing dev database with
     legacy rows (NULL expires/admin key) no longer loads — the data file
     must be recreated. Full `-race` suite green.
