# Prompt log

Verbatim log of the prompts given to the agent in this repository, grouped
per session day. The prompts are the project's steering history: they
survive agent-session compaction and can be handed to a fresh agent
verbatim.

Conventions:

- Prompts are quoted exactly as given, typos and all.
- A short note follows each prompt: what it produced or decided.
- Entries marked *(wording lost)* belonged to a compacted conversation
  whose summary preserved only the substance.
- Transcript markers like "function call failed" in Zed's thread history
  are failed agent tool calls (e.g. truncated write batches), not user
  prompts, and are not logged here.
- Entries are appended automatically with every prompt — verbatim plus
  a one-line outcome note, written before the session summary (rule in
  `AGENTS.md` → Conventions).

## 2026-10-31 — security review (analysis only)

1. "Focus on security. Analyze this codebase thoroughly and give me a list of potential security vulnerabilities (sql injections, DoS attacks, etc.). Propose mitigations for each problem. `AGNETS.md` describes the project and in `docs/prompts/...` you find the past development work. Don't implement anything yet. Just propose mitigations."
   → Security audit, no code changes. Findings: no SQLi (GORM
     parameterizes every query); a latent reflected-XSS / MIME-sniffing
     gap on 4xx responses that echo user input (no
     `Content-Type: text/plain`, no `X-Content-Type-Options: nosniff`);
     a render-time DoS from an unbounded candidate-slot count and
     unbounded `title`/`description`/`email` (only the 4 MB body limit
     caps them); no rate limiting on unauthenticated poll creation /
     answers; missing headers (`nosniff`, `Secure` cookie flag, broader
     CSP); dev-only template `Reload(true)`/`Debug(true)` left on; and
     several low-severity items (internal `err.Error()` leakage, link
     keys in the request logger, Host-header-fed link boxes, `dater.js`
     `innerHTML` pattern). Mitigations proposed for each.
