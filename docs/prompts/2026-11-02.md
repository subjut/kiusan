# Prompt log

Verbatim log of the prompts given to the agent in this repository, grouped
per session day. The prompts are the project's steering history: they
survive agent-session compaction and can be handed to a fresh agent
verbatim.

Conventions:

- Prompts are quoted exactly as given, typos and all.
- A short note follows each prompt: what it produced or decided.
- Entries marked *(wording lost)* belonged to a compacted conversation
  whose summary preserved only the substance.
- Transcript markers like "function call failed" in Zed's thread history
  are failed agent tool calls (e.g. truncated write batches), not user
  prompts, and are not logged here.
- Entries are appended automatically with every prompt — verbatim plus
  a one-line outcome note, written before the session summary (rule in
  `AGENTS.md` → Conventions).

## 2026-11-02 — 1-1-form picker polish

1. "Read AGENTS.md.
Then make the following improvements to 1-1-form:
- Shrink the width of the dropdown menus "poll ends" and "timezone" to correspond to the widest possible content.
- When adding a timeslot to all dates, there is a bug: when I click on the clock symbol to open the time menu that is for example set to 6:00 pm (current computer time) and I click on the minute 03, it adds 6:00, 6:01, 6:02, and 6:03 p.m. as timeslots. The time window stays open and I have to click beside it to close it. The same also happens, when I scroll through either hours or minutes, adding each hour to the timeslots for each date. The button "Add to all dates" does nothing. The desired behavious is, to select a time, then click the "Add to all dates" button, and then the timeslot is added to all dates. I noticed a similar behaviour with the time selection for each date, but there, it does not matter, because the "Add" button works. If you have a better suggestion, tell me.
- Shrink the time selection menus for each date to fit the content."
   → Fixed the "Add to all dates" bug by removing the `change`
     listener on `#time-input` in `static/js/dater.js` (it auto-applied
     the time on every intermediate selection step and cleared the value,
     so the button then had nothing to add); the time now applies only
     on the explicit "Add to all dates" click (or Enter) and the picker
     closes normally. Sized `#enddate` + `#timezone` to `width: auto`
     (fit content) and bumped the per-date time-input selector to
     `input[type="time"].date-time-input` so its `width: auto` override
     actually beats the generic `input[type="time"] { width: 100%;
     max-width: 480px; }` rule it had been losing to on specificity.

     mirroring the existing click delegation; Enter now adds the time to
     that date, same as clicking the row's "Add". The "add to all dates"
