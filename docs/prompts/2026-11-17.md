1. "Read AGENTS.md. When the answer table gets really big, the user always has to scroll up to see the header with the dates/voting options. What would be the best way to keep the header of the answer table in view, when the user scolls down? Make me an inplementation proposal, ask questions and give me options to decide on, and give me the final options on how to proceed."

   proposed two approaches (bounded scroll box with pinned `thead` vs. a JS
   cloned sticky header); the user chose the bounded box, pinning all of the
   meeting's header rows (year/date/time), without pinning the form row to the
   bottom. Implemented: `.table-scroll` became the table's bounded vertical
   scroller (`max-height` + `overflow: auto`), the `thead` pins via `position:
   sticky` per row (tops from row heights measured in `page.js` as `--th-2`/
   `--th-3`, activated by the `table-sticky` class, re-measured on resize and
   on `Locale.onChange`), and `.answers-table` switched to
   `border-collapse: separate` for Chrome's sticky-border bug (visually a
   no-op — cells draw only right + bottom borders). Verified: go
   build/vet/test, node --check, jstest 40/40 (new sticky-activation test),
   server on test.db serving the 100×100 table 200; AGENTS.md updated (Layout,
   jstest bullet, new Sticky table header gotcha).
