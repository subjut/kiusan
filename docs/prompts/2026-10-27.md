# Prompt log

Verbatim log of the prompts given to the agent in this repository, grouped
per session day. The prompts are the project's steering history: they
survive agent-session compaction and can be handed to a fresh agent
verbatim.

Conventions:

- Prompts are quoted exactly as given, typos and all.
- A short note follows each prompt: what it produced or decided.
- Entries marked *(wording lost)* belonged to a compacted conversation
  whose summary preserved only the substance.
- Transcript markers like "function call failed" in Zed's thread history
  are failed agent tool calls (e.g. truncated write batches), not user
  prompts, and are not logged here.
- Entries are appended automatically with every prompt — verbatim plus
  a one-line outcome note, written before the session summary (rule in
  `AGENTS.md` → Conventions).

## 2026-10-27 — poll answering feature: implementation

1. "go"
   → Implemented the approved plan end to end: two random links per poll
     on one route (user + admin, admin view picked by key match), the
     respondent page (name box, green / yellow-(✓) / red marks, answer
     matrix, description above the table, single-slot greying enforced
     server-side, yellow omitted), per-poll identity cookie (HttpOnly,
     SameSite=Lax, valid until poll end — 90 days for legacy polls) with
     stateless HMAC-SHA256 CSRF tokens (KIUSAN_SECRET), admin page
     (copyable links, edit-poll back to the prefilled 1-1 form keeping
     both links, edit/delete of any answer, organizer answers through
     the same cookie), poll expiry with organizer prolongation, legacy
     polls without an admin link (nullable unique `admin_key`),
     clickjacking headers, urlencoded-only POST gate. Storage gains
     `GetAdmin` + a CAS `Update` (Generation). Fixed along the way: the
     checkbox `value` 400s, a missing first-visit CSRF token, and a
     `$.` bug in the answers matrix. New `poll_test.go` lifecycle suite
     plus the existing suites pass on pudge and sqlite, with `-race`.

2. "Bug: when submitting an answer, I cannot select the available or maybe option. Also, they are not color coded. The whole page does not seem to use CSS. Lastly, I want to flip the table. The answers are in rows, the date/time options are in the columns."
   → Root cause: asset references in the templates were relative (`./style.css`,
     `./poll.js`, `./dater.js`, favicon/manifest in the head partial), so on deep
     routes like `/meet/<key>` the stylesheet and scripts 404'd — dead mark
     buttons and no colours, while `/` happened to work. All asset refs are now
     root-absolute. The CSS colour rules existed already but also got tinted
     backgrounds for `st-g`/`st-y`/`st-r` cells so marks read as colour at a
     glance. Flipped the "Submitted answers" matrix: respondents are rows (the
     per-respondent `Syms`/`Csls` arrays already built for the admin cards,
     `(you)` marker included) and the date/time options are columns; pruned the
     now-unused `rows`/`slotlabels`/`ansCell` from `meetingHandler`. build/vet/
     full test suite green on both backends with `-race`.

3. "When the admin adds or edits his answer, he should be redirected back to the admin page. Currently, he lands on the user page."
   → View-key fix in `meetingHandler`: forms now post through the link the
     page was viewed on, so the back-redirect lands on the admin page. An
     admin's delete-own via the admin link stays a capability post (keeps
     the identity cookie). The poll suite pins the redirects and the form
     actions on both views.

4. "The redirection back to admin page works now. Can stop running in circles."
   → Redirect confirmed working. The red test was my own assertion typo (a
     stray `"` in the expected `action="…` string — 39 bytes wanted vs the
     38 the page renders); stripped the debug instrumentation and scratch
     test, corrected the assertions; suite green on both backends with `-race`.
