# Prompt log

Verbatim log of the prompts given to the agent in this repository, grouped
per session day. The prompts are the project's steering history: they
survive agent-session compaction and can be handed to a fresh agent
verbatim.

Conventions:

- Prompts are quoted exactly as given, typos and all.
- A short note follows each prompt: what it produced or decided.
- Entries marked *(wording lost)* belonged to a compacted conversation
  whose summary preserved only the substance.
- Transcript markers like "function call failed" in Zed's thread history
  are failed agent tool calls (e.g. truncated write batches), not user
  prompts, and are not logged here.
- Entries are appended automatically with every prompt — verbatim plus
  a one-line outcome note, written before the session summary (rule in
  `AGENTS.md` → Conventions).

## 2026-11-05 — dark mode (light/dark theme)

1. "Implement dark mode. Requirements:
- It should default to the preconfigured system settings.
- It should have a toggle button somewhere in the header, maybe beside the language switcher, to switch between light and dark mode. It shoud have a nice svg symbol.
- It should follow the warm color scheme.
- It should be high contrast for good readability.
Do you have other suggestions? Ask questions for the direction to take, as many as it needs to make it clear what I want."
   → No code written. Researched the existing token-based design
     system (`static/css/style.css` `:root` custom properties, single
     teal accent, `@layer theme, base, components`) and the i18n /
     cookie architecture, then asked three direction questions
     (control behavior, persistence, dark accent).

2. Direction decisions (answers to the three questions):
   - Control: "Two state, icon only, no lable"
   - Persistence: "Cookie kiusan-theme (my suggestion): the server
     renders the theme class, so pages load in the right theme with
     zero flash, no extra blocking request; consistent with the
     existing kiusan-locale cookie architecture."
   - Accent: "Teal, brightened for dark surfaces (keeps the
     single-accent identity — my suggestion)"
   → Fixed the design: a two-state icon-only sun/moon toggle beside
     the language select, persisted in a `kiusan-theme` cookie that
     `main.go` renders as a class on `<html>` (no flash), and a
     brightened teal accent carried through a re-targeted set of warm
     stone dark tokens.

3. "Don't forget to look at AGENTS.md"
   → Re-read `AGENTS.md` and applied its conventions: re-read every
     template after writing it (tag nesting verified balanced), added
     a `Theme` entry to the Gotchas and updated the `static/` layout
     entry, and logged this session to `docs/prompts/`.

   Implementation (prompt 1 + decisions):
   - `main.go` — `pageData.ThemeClass` + `themeClass(c)` helper (reads
     the `kiusan-theme` cookie: `dark`→`theme-dark`, `light`→
     `theme-light`, absent/invalid→"" so the CSS media query follows
     the system) set in `renderPage`.
   - `static/layouts/home.html` — `class="{{.ThemeClass}}"` on `<html>`
     (conditional, so no class while the system setting is in effect).
   - `static/partials/head.html` — `<script src="/theme.js">` (loaded
     before `style.css` and `locale.js`) and two `meta theme-color`
     tags (light + `prefers-color-scheme: dark`).
   - `static/partials/theme-toggle.html` — new partial: a 44px ghost
     button `#theme-toggle` with an inline sun SVG and moon SVG (the
     visible icon always offers the switch to the *other* theme).
   - `static/partials/header.html` — locale select + theme toggle
     grouped in a `.header-actions` span.
   - `static/js/theme.js` — new (vanilla, no deps): resolves the
     effective theme (explicit `kiusan-theme` cookie wins, else system
     `matchMedia`), follows live system changes while no cookie is
     set, and on click flips the theme, mirrors it onto the same
     `theme-dark`/`theme-light` classes, and persists it to the cookie
     (1-year, Lax). Refreshes the localized `aria-label` from
     `window.I18N` on every flip and on `Locale.onChange` (so a
     language switch re-labels it).
   - `static/css/style.css` — (a) the dark theme as two identical token
     re-target blocks (warm stone neutrals, brightened teal accent,
     light-glyph-on-dark-tint answer marks, darker elevation) under
     `@media (prefers-color-scheme: dark)` scoped to
     `:root:not(.theme-light)` and under `:root.theme-dark`;
     (b) tokenized the last hardcoded colors — new `--on-accent`,
     `--danger`/`--danger-hover`/`--on-danger`, `--shadow-hover` — so
     buttons, the delete-poll action, selected calendar days, and the
     card hover shadow all follow the theme; (c) `.header-actions` and
     `.theme-toggle` component styles, with the sun/moon icon swap as
     pure CSS from the `<html>` classes; (d) `.theme-toggle` added to
     the `forced-colors` rule. Every text/surface pair is ≥AA.
   - `locales/en.yaml` + `de.yaml` — new keys `nav.themeLight` /
     `nav.themeDark` ("Switch to light mode" / "In den hellen Modus
     wechseln" + German), no `{{` in values.
   - `smoke_test.go` — new `TestThemeCookieContract` pinning the
     no-flash contract (cookie→`<html>` class mapping, absent/invalid
     cookie→no class, toggle present in the header).
   - `AGENTS.md` — Layout `static/` entry now lists `theme.js` +
     `theme-toggle.html`; `style.css` description notes the two themes;
     new Gotcha "Theme (light/dark)".
   - Validation: `go build ./...`, `go vet ./...`, `go test ./...` and

4. "There are many bugs:
- The content width suddenly streches over the complete browser width, e.g. the K logo is on the left side of the browser window and the theme toggle button is on the right side.
- My system is set to dark mode, but the page displayed in light mode.
- Clicking the button does not swicht the modes. It stays in light mode.
- Clicking the button switches the display of the button between the sun symbol only, and the sun combined with the moon symbol. While you're fixing this, change the symbol to be the symbol of sun in the upper left corner, then a diagonal slash, and the moon symbol in the lower right corner. It should always stay like this, just switch color between dark and light mode.
- There is now a link "Skip to content" above the Kiusan logo in the header that was not there previously and should not be there.
Fix all this and test thoroughly."
   → Root cause of the layout/dark bugs: an **unclosed `/*` comment**
     above the dark-theme block in `style.css` (the "Warm stone
     neutrals …" header comment was missing its `*/`), so the browser
     treated everything up to the first inner `*/` as one comment —
     swallowing `@layer theme {`, `@media (prefers-color-scheme: dark)
     {` and `:root:not(.theme-light) {` and desyncing the parser through
     the following `@layer base` (`.container`, `.skip-link` lost →
     full-width header, visible skip link; dark tokens lost → system
     dark rendered light, clicks changed nothing). Fixed by closing the
     comment. Toggle icon redesigned per request: `static/partials/
     theme-toggle.html` now carries ONE fixed SVG — sun (core + 8 rays)
     top-left, diagonal slash (anti-diagonal divider), scaled feather
     crescent bottom-right — all `currentColor`, always visible; the
     color switches with the theme, no icon swapping. The two-icon
     show/hide CSS (`.theme-icon-sun/-moon` + media/class rules) was
     removed. Testing: comment-stripped brace audit of `style.css`
     (151/151, min depth 0, no unterminated comment), a clean server
     run + curl verifying the served HTML carries the new single icon
     (and no `theme-icon-sun`), `go vet ./...` and `go test ./...` pass.
     Note: `write_file` of the first icon attempt combined a
     full-canvas "auto" crescent with the small sun (overlapping) —
     re-derived as the explicit three-part composition; re-read the
     template after writing per the project rule.
